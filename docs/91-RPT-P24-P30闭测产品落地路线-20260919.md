## MVP 真正落地终点

项目从“技术候选”进入“可给受控用户使用的 Android 闭测产品”，必须完成以下真实链路：

```text
正式签名 Android App
  → 创建拍摄项目
  → 导入自己的参考照片
  → 至少一种可信 AI 来源（批准离线知识或本机 Qwen）
  → 理解场景/光线/构图/姿态意图/机位/拍摄建议
  → 选择主参考
  → Camera Director
  → 拍照与导出
  → 杀进程/重启后项目和指导状态正确
  → 真实手机
  → 5 人 Pilot
  → P0/P1 修复
  → 受控闭测
```

现有三条产品路径仍需保持边界：

- 无 AI 指导：可用于离线基础拍摄，但不得冒充真实分析；
- 批准 Photo Knowledge Bundle：提供有来源的离线逐张指导；
- 本机 Qwen：`连接本机 Qwen → 逐张 READY → READY-only 汇总 → AI Camera Director`。

## P24 — Release Signing & Distribution

P23D 的标准 Gradle 阻塞是 `PHOTOAI_RELEASE_STORE_FILE` 缺失，而不是代码编译失败。这是当前变成可分发软件的第一现实 Gate。

### 只允许的第一步

只读检查 Owner 是否已有之前 Beta 使用的签名材料和对应证书：

```text
PHOTOAI_RELEASE_STORE_FILE
PHOTOAI_RELEASE_STORE_PASSWORD
PHOTOAI_RELEASE_KEY_ALIAS
PHOTOAI_RELEASE_KEY_PASSWORD
```

如果已有，只允许通过环境变量使用；密码、keystore、绝对私人路径不得写入 Git、报告或 Obsidian。若没有，停止并记录：

```text
P24_BLOCKED_OWNER_SIGNING_DECISION
```

由 Owner 决定恢复旧签名，或正式创建长期 signing identity。Codex 不自动生成生产 keystore。

### P24 交付证据

仅在 Owner 提供合法签名材料后，生成仓库外 `app-release.apk` / `app-release.aab`，并记录脱敏摘要：source SHA、versionName、versionCode、证书 SHA-256 fingerprint、APK/AAB SHA-256、构建环境。签名产物不进入 Git。

## P25 — 第一份真实摄影知识

P23C 解决的是知识包审核/打包工具，不等于已有真实可用摄影知识。P25 的目标是产生 20 条真实、可审核、可追溯的摄影知识，而不是继续扩展 Bundle infrastructure。

每条知识至少保留 v1 合同字段：`scene`、`background_story`、`lighting`、`composition`、`subject_intent`、`emotion`、`pose_template`、`camera_position`、`director_prompt`。

内容流程必须是：

```text
来源素材
  → AI 候选分析
  → 人工摄影质量审核
  → 隐私审核
  → 权利/来源审核
  → 修正
  → 最终 APPROVED
```

工具测试中的 synthetic `APPROVED` 不能冒充人工审核。闭测内容应有稳定 ID，例如 `PKB-PORTRAIT-001` 至 `PKB-PORTRAIT-020`，并绑定 `source_evidence_id`、`review_id`、`reviewer_id`、`evidence_id` 和 bundle release id；不得保存文件路径、EXIF、用户名或设备 ID。

P25 完成不等于 App 自动信任该 Bundle；信任机制属于 P26。

## P26 — Knowledge Pack Trust

### P26-A：闭测 pinned registry

第一版闭测优先在 App 内编译 `ApprovedKnowledgeBundleRegistry`，记录 `producer_id`、`release_id` 和 `payload_sha256`。导入顺序为：Schema valid → PKB1 digest valid → producer/release valid → payload hash 在 App allowlist → 显示“已批准闭测知识”。格式正确但来源未批准时，不得显示官方知识状态。

这避免第一次闭测同时引入 CA、证书链、轮换、吊销和远端 key discovery。

### P26-B：正式动态签名

产品价值验证后再做 `Photo Knowledge Release Envelope v1`，包含 `bundle.json`、`release-manifest.json`、`signature`、`key_id`，由内置 root public key 验证签名、Bundle SHA、PKB1 和 release_id。不要在第一次闭测前把它扩张成企业级证书平台。

## P27 — Real Qwen LAN

P27 才是让真实 AI 链路活起来的阶段。现有 Provider/Room/Summary/恢复代码可以作为连接点，但当前合成 Provider PASS 不能外推为真实模型资格。

### 分层 Gate

1. **环境资格**：只读检查物理网络、Windows network profile、Qwen 环境、模型文件 hash、Python、GPU、端口和证书；禁止以 FlClash、WSL、VPN、虚拟网卡作为手机入口。
2. **服务资格**：沿用已授权的 Qwen3-VL-2B 路径，验证 localhost health、TLS、certificate pin、pairing code、session、timeout、cancellation 和 schema。
3. **手机 LAN**：`pair → pin → health → one synthetic request`，先不读取真实照片。
4. **5 张 smoke**：只读取 Owner 明确授权的照片，验证照片绑定、不串图、旧响应隔离、READY provenance 和 fail-closed。
5. **20 张 qualification**：记录 READY/FAILED/timeout、P50/P95、schema validity 和 summary validity；旧 P20 结果不替代当前 main/当前协议的新鲜证据。

P27 退出：`P27_REAL_LAN_ANALYSIS_QUALIFIED`。

## P28 — Physical Device Qualification

实体设备必须在 P27 后进入，且不能使用无筛选的 `adb devices → 全部 install`。流程固定为：明确 serial → 确认型号 → Owner 确认 → 才允许同签名安装。

至少两类真实 Android 设备覆盖：安装/升级、Photo Picker 多选/取消/权限、20 图项目导入/删除/恢复、Bundle 导入/映射/重启、Qwen LAN、Camera 预览/拍摄/旋转、相册保存、后台/kill/restart、100/200% 字体、权限拒绝/恢复、LAN 中断/恢复、内存/ANR/启动。

## P29 — 5 人 Pilot

Pilot 阶段不做功能扩张。Codex 负责构建、安装、脱敏日志、问题整理、复现和修复；人负责判断指导是否有用、UI 是否易懂、操作是否自然以及等待是否可接受。

每位用户至少完成：新建项目、导入参考、尝试知识包、选择主参考、使用 AI Director、拍摄、导出、退出并次日重开。优先级固定为：

```text
P0 crash/data corruption/privacy
  → P1 workflow blocker
  → P2 usability
  → feature request
```

实时 Pose、新模型和大规模 UI 改造在 Pilot 阶段降级。

## P30 — 受控闭测

5 人 Pilot 稳定后，再进入至少 10 名受控测试者、至少 2 类真实设备、持续 14 天的正式闭测。冻结 versionCode、versionName、signing identity、knowledge release、model identity、LAN protocol 和 DB schema，只允许 bug fix。交付包括 signed AAB、release notes、privacy manifest、support guide、known issues、rollback plan 和闭测资格记录；之后才讨论公开发布。

## 固定执行纪律

每个阶段只解决一个“为什么现在还不能给用户用”的问题：

```text
READ
→ FREEZE BASE SHA
→ CREATE ISOLATED WORKTREE
→ IMPLEMENT ONE GATE
→ POSITIVE TEST
→ NEGATIVE TEST
→ PRIVACY
→ DIFF REVIEW
→ COMMIT
→ PUSH
→ LOCAL QUALIFICATION
→ INDEPENDENT REVIEW
→ LAND
→ STOP
```

禁止顺手换模型、加 Pose、改 UI、接 Pipeline 或未经授权合 main。每一个候选 PASS、main 合入、真实 Provider、签名发布和生产授权都必须绑定自己的精确证据。
